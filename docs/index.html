Give Codex a safe way into your Canvas.

canvas-mcp is a small local source project that connects Codex to your own Canvas account. Start read-only. Add writes only if—and when—you choose.

1

Understand what this is

A local bridge between Codex and one instructor's Canvas account. You run it, you hold the token, and you decide whether changes are ever allowed.

What it can help with

  • List and search your courses.
  • Read assignments, pages, modules, and files.
  • Find missing or late submissions.
  • Summarize activity and course content.
  • Draft feedback and announcements.
  • Optionally create rubrics and grade with them.

What it is not

  • Not a hosted Canvas proxy.
  • Not a browser extension.
  • Not a global Python install.
  • Not supported by your institution.
2

Let Codex install the tagged source

On the Mac or Windows computer where Codex runs, paste one prompt into a local Codex task. A phone or tablet can display this guide but cannot perform the installation. Codex checks the release tag, creates an isolated Python environment, runs the tests, and stops before the secret step.

Install canvas-mcp v0.1.1 from https://github.com/chiptoe-svg/canvas-mcp.git at ~/canvas-mcp.
Use only the exact published tag; never substitute main, and do not overwrite an existing folder.
After cloning, read AGENTS.md, create .venv, install ".[test]", and run pytest. Run
connect_canvas.py status. If disconnected, give me the visible-terminal `connect` command and
wait while I enter the token at its hidden prompt. After I say done, verify status, register only
the read-only `canvas` server with `codex mcp add`, run `connect_canvas.py install-skill --apply`,
and verify with `codex mcp get canvas`. Never request my token or make a Canvas write.

Why a tag? A named release is an immutable point you can review. The setup prompt refuses to silently substitute the moving main branch.
3

Connect your Canvas account

This is the one step you perform yourself. The token belongs only in the hidden prompt of a terminal you control—never in Codex chat.

  1. In Canvas, open Account → Settings → Approved Integrations → + New Access Token. Give it a purpose and an expiry date.
  2. Run the exact connection command Codex prints. In a standard macOS checkout it is:
cd ~/canvas-mcp
.venv/bin/python connect_canvas.py connect
  1. Check the displayed Token destination hostname, then paste the token at the hidden prompt.
  2. Return to Codex and reply done. Codex re-checks status and registers the read-only server.

Where the secret goes

The token is saved only in macOS Keychain or Windows Credential Manager. It is not stored in this project, a config file, an environment variable, shell history, or Codex configuration.

Bad URL? Unsafe forms are rejected and re-prompted before the token. A valid-looking typo cannot be recognized by spelling alone, so check the printed hostname.

4

Start read-only

Use the connection for ordinary questions before considering writes. With the default configuration, every apply tool refuses and sends nothing.

Try a small, specific request

Using canvas-mcp, list my active Canvas courses. Return only each course name and course ID.

Ask for only the fields the task needs. Smaller responses reduce the amount of student information sent to the model.

Read-only still handles real data

Anything returned by a Canvas tool reaches the AI model Codex is using. Your institution's policies on student records, personal access tokens, and AI services still apply.

Paste this into Codex — not Terminal

Ask Codex to prepare your exact write settings

Codex will inspect your existing setup, make one read-only Canvas connection check, and print only the change you need. It will not edit your configuration or change Canvas.

Help me enable writes in my tagged canvas-mcp checkout at ~/canvas-mcp. Read AGENTS.md, run the
tests and `connect_canvas.py status`, then run `connect_canvas.py setup-info --writes`. Do not
edit config.toml or Canvas. Inspect my existing `canvas` MCP entry and print only the exact
replacement block, preserving unrelated settings and excluding rubrics. Show me how to make a
unique verified backup, open config.toml in a text editor, replace—not duplicate—the block, and
restart Codex. Keep top-level `approvals_reviewer = "user"` and the server's
`default_tools_approval_mode = "writes"`.

Then open one file—not Codex Settings

The current desktop Settings screen does not expose the documented Open config.toml control. That control is for the Codex IDE extension.

  1. On macOS, open Terminal and run the command below. It creates a unique backup, prints its location, and opens the real file in a plain-text editor.
backup_dir="$(mktemp -d "$HOME/.codex/canvas-mcp-config-backup.XXXXXX")" &&
cp -p "$HOME/.codex/config.toml" "$backup_dir/config.toml" &&
cmp -s "$HOME/.codex/config.toml" "$backup_dir/config.toml" &&
printf 'Verified backup: %s\n' "$backup_dir/config.toml" &&
open -t "$HOME/.codex/config.toml"
  1. In the editor that opens, replace the existing [mcp_servers.canvas] block with the block Codex printed. Do not add a second block.
  2. Save the file, close and reopen Codex, then ask Codex to verify the Canvas server configuration.

On Windows, ask Codex for the equivalent PowerShell backup-and-open commands; the complete Windows setup path is not yet tested.

Where future confirmations appear

The server requests confirmation through the MCP client. Presentation can vary, so after restarting ask Codex to call canvas_test_confirmation. It exercises the real gate but cannot contact or change Canvas.

Advanced: print the settings yourself in Terminal

Run this in Terminal

cd ~/canvas-mcp
.venv/bin/python connect_canvas.py setup-info --writes

This prints the write-only block. Add --enable-rubrics to the command only when you deliberately want rubric tools and their longer timeout.

Never retry an uncertain write. If a result says WRITE STATUS UNCERTAIN, the request may have reached Canvas even though the response was lost. Inspect the object in Canvas or read it back before doing anything else.

Rubrics are another explicit opt-in

Add "--enable-rubrics" only if you need rubric creation or guarded batch grading, and set tool_timeout_sec = 600. Rubric grading limits batches to 50 ungraded students, validates the live rubric, re-checks before each write, and reads each result back. By default it moves automatic posting to manual before the first grade. If you deliberately set keep_post_policy=true, it does not make that change and grades may become visible immediately.

6

Update when you choose

Nothing updates automatically. Use the quick option to repair the installed skill, or update the tagged project and skill together.

Paste either short prompt into Codex — the scripts enforce the checks

Refresh the skill

Quick repair. Keeps the currently installed server release and refreshes only Codex's matching workflow instructions.

In ~/canvas-mcp, run `.venv/bin/python connect_canvas.py install-skill`, show me the preview,
and wait. After I approve, run it again with `--apply`, report the verified backup and result,
then tell me to restart Codex. Do not edit Codex configuration or call Canvas.

Update everything recommended

Moves to the newest published release you authorize, reinstalls its dependencies, tests it, and refreshes the matching skill.

In ~/canvas-mcp, run `.venv/bin/python update.py check`, show me the exact current and target
tags, commits, and release notes, then wait. After I approve that named tag, run
`.venv/bin/python update.py apply TAG` with that exact tag. Report the test and skill-backup
results and tell me to restart Codex. Do not edit config.toml or call Canvas.
One-time update from v0.1.0

Version 0.1.0 predates update.py. Paste this into Codex once; later releases use Update everything above.

Upgrade my existing ~/canvas-mcp from v0.1.0 to exactly v0.1.1. Read AGENTS.md. Verify the
checkout is clean, origin is https://github.com/chiptoe-svg/canvas-mcp.git, and remote v0.1.1 is
contained in origin/main. Show me its commit and changelog, then wait. After I approve, switch
detached to that exact commit, reinstall ".[test]", run pytest, and run
`connect_canvas.py install-skill --apply`. Do not edit config.toml, request a token, or call Canvas.
Why not download only the newest skill? The skill teaches Codex how to use this server's exact tools and safeguards. Keeping the skill and tagged server release together prevents mismatched instructions.

The installer refuses symlinks, Windows junctions, and installed-file changes it observes. Like any user-owned file operation, it cannot defend against a malicious process already running as you and racing directory changes; close editors or sync tools that modify the skill while installing.

!

Know the safety boundaries

The project is designed to fail closed, but it still connects an AI tool to your real instructor account. These are controls—not a substitute for policy or judgment.

One locked Canvas host

REST requests are locked to the configured HTTPS host and /api/v1. The only path exception is one fixed GraphQL post-policy mutation used by guarded rubric grading. Redirects, other hosts, traversal paths, and credential-management endpoints are refused.

Token stays out of model-visible input

The server reads it directly from the approved operating-system credential store at request time and uses it only in the authorization header.

Student data may reach the model

Course data returned by a tool is visible to Codex. Follow your institution's FERPA, privacy, records, and AI-use requirements.

Community project, early release

Version 0.1.1 is not an official Instructure or institutional product. Windows connection support exists, but the complete Windows setup and uninstall path has not been tested on a Windows computer.

7

Remove it when you're done

The uninstaller previews its plan and asks before removing anything. It refuses to delete a project folder containing files it does not recognize.

Run from the project folder

cd ~/canvas-mcp
.venv/bin/python uninstall.py

Use --keep-project if you want to remove the stored connection and skill but preserve the source checkout.

Two manual clean-up steps remain

  1. Delete the canvas server block from Codex configuration; the project never edits that file automatically.
  2. Revoke the token in Canvas under Account → Settings → Approved Integrations. Removing it locally does not revoke it in Canvas.
